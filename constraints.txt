# Exact versions TeleVault is tested against (runtime + dev tools, including indirect dependencies).

# requirements.txt says what we NEED ("fastapi", "sqlalchemy>=2.0"); this file says what we have actually RUN.
# Install with:
#     pip install -r requirements-dev.txt -c constraints.txt
# A constraints file never adds packages, it only limits which versions pip may pick for packages that are installed anyway,
# so entries that do not apply to your platform (uvloop, httptools and watchfiles are skipped on Windows) are simply ignored.
#
# Why it exists: with unpinned requirements, `pip install` today and in six months can give different FastAPI/Starlette/SQLAlchemy versions.
# An upstream release can then break the app or the tests with no change in this repo.
# Pinning makes installs reproducible and makes every dependency upgrade a deliberate, reviewable commit that has to pass the test suite first.
#
# Updating (do it now and then, and after security advisories):
#     python -m venv /tmp/fresh && /tmp/fresh/bin/pip install -r requirements-dev.txt     # latest allowed by requirements*.txt
#     /tmp/fresh/bin/python -m pytest                                                      # must pass
#     /tmp/fresh/bin/pip freeze > constraints.txt                                          # then re-add this comment block, review the diff
# Generated with Python 3.13 on Linux. Packages Windows does not need will appear here too, which is harmless.
#
